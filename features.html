核心特性

1. 极致轻量

moco 的整个运行时是一个 C 编译出的单一可执行文件。启动器本身不消耗系统资源 —— 没有后台服务，没有 Electron 外壳，没有运行时依赖。安装只需要一个二进制文件和一个配置文件。

2. 全生命周期管理

从零开始，一条命令链覆盖 Minecraft 实例的完整生命周期：

moco init      → 初始化工作目录和配置文件
moco login     → Microsoft OAuth2 设备码登录
moco install   → 下载 Minecraft 版本 + 模组加载器 + 模组
moco start     → 启动游戏

此外还支持 moco search 搜索版本、moco update 更新版本清单、moco import 导入 Modrinth 格式的模组包。

3. 模组加载器与整合包

moco 支持 Forge、NeoForge、Fabric 三大主流模组加载器，安装和启动流程对每种加载器都做了完整的适配 —— 包括各自的 JSON 参数解析、library 依赖追加、以及正确的 mainClass 替换。

同时支持导入 Modrinth 格式的整合包（.mrpack），一条命令即可将别人分享的整合包还原为可运行的 Minecraft 实例，自动生成 instance.toml 并解压覆盖文件。

4. 基于内容寻址的智能存储

所有下载的文件通过 SHA1 校验和存储到内容寻址存储（~/.local/share/moco/store/v1/），然后通过硬链接引用到目标路径。原理与 pnpm 的全局 store 相同：

  • 全局去重 — 相同的文件只下载一次，无论多少个实例引用它
  • 完整性验证 — 每个文件下载后自动校验 SHA1，失败自动重试
  • 天然的多实例隔离 — 每一个文件夹就是一个独立的实例，文件共享由底层的内容寻址存储透明完成

详见 存储引擎。

5. 异步并发下载引擎

基于 epoll + curl_multi 的自研下载引擎：

  • 最多 16 个并发连接，每主机 6 个连接
  • 实时进度条显示（VT100 终端控制）
  • 自动重试和 SHA1 完整性校验
  • 通过管道通信的后台任务提交机制

6. Microsoft OAuth2 完整认证链

实现了完整的 Xbox Live 认证链：设备码授权 → XBL → XSTS → Minecraft Token，支持 token 自动刷新。启动游戏时自动续期，无需用户手动重新登录。

7. 安全透明

  • 开源 — 代码完全开放，可以审查每一行
  • 本地优先 — 所有数据存储在本地，配置是 TOML 明文，没有遥测
  • 进程隔离 — 通过 fork() + execvp() 分离启动器和游戏进程
  • 无管理员权限 — 不需要 root，不需要修改系统配置
